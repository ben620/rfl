## 测试方法

基准程序位于 `benchmarks/json_benchmark.cpp`，构建目标为 `rfl_benchmarks`。

- 每个用例先预热 `iterations / 10 + 1` 次
- 正式测量 3 轮，**取最优值**，轮次之间休眠 2 ms 以降低热降频影响
- 通过重载全局 `operator new` 统计堆分配次数与字节数
- 使用 `volatile` 汇聚变量防止结果被优化消除
- 支持按名称过滤：`rfl_benchmarks.exe <关键字>`

运行方式：

```
cmake -S . -B build
cmake --build build --config Release
build\Release\rfl_benchmarks.exe
```

## 优化项清单

### 输出层（参考 `std::format` 的连续缓冲设计）

| 优化 | 说明 |
|---|---|
| 本地栈缓冲 | `ToJson` 默认先写入 256 字节栈缓冲 |
| 几何扩容 | 溢出后按约 1.5 倍增长 |
| 复用容量 | 新增 `ToJson(value, std::string&)` |
| 长度预计算 | 新增 `JsonSize(value)`，等价 `formatted_size` |
| 单字符快速路径 | `{`、`}`、`,`、`:` 直写缓冲 |
| 字面量重载 | `append(const char(&)[N])` 免去 `strlen` |
| 去除清零 | 数字缓冲与 4 KiB sink 缓冲不再值初始化 |

### 数字与字符串

| 优化 | 说明 |
|---|---|
| `std::to_chars` | 无 locale、无临时字符串 |
| 最短浮点格式 | `0.1` 输出 `0.1` 而非 `0.10000000000000001` |
| 转义快速路径 | 普通字节仅做紧凑判断，按连续区段批量复制 |
| 字段名免扫描 | 反射字段名是合法标识符，无需转义检查 |

### 反射遍历

| 优化 | 说明 |
|---|---|
| 单次 tie | 消除每字段重建引用 tuple 的 \(O(N^2)\) 行为 |
| 短路遍历 | 新增 `for_each_member_while`，`&&` fold 真正提前退出 |
| 编译期逗号 | 由字段索引在编译期决定，去掉运行时 `first` 标志 |

### 反序列化

| 优化 | 说明 |
|---|---|
| 视图化字符串 | 无转义时直接 `assign` 视图，不逐段解码 |
| 键名零分配 | `parse_key` 返回 `string_view` |
| 语法级跳过 | 未知字段只验证语法，不解码不分配 |
| 长度预筛 | 字段匹配先比长度再比内容 |
| 匹配短路 | 命中字段后立即停止遍历 |
| 原地构造 | `emplace_back` 后直接解析，省掉一次移动 |

### 网络输出

| 优化 | 说明 |
|---|---|
| 分块聚合 | 默认聚合到 4096 字节再调用 sink，减少系统调用 |
| 大块直通 | 超过缓冲的数据直接发送，省一次 `memcpy` |
| 部分写入 | sink 可返回消费字节数，自动重试剩余部分 |

## 尝试后回退的优化

**`vector` 容量启发式 `reserve`**

按剩余输入长度估算元素数量并预留容量。实测导致过度分配与堆碎片：

| 用例 | 无 reserve | 带 reserve | 结果 |
|---|---|---|---|
| Track(嵌套 5k) | 477.5 μs | 1759.8 μs | 慢 3.7× |
| Message(64K) | 29.4 μs | 156.6 μs | 慢 5.3× |

虽然 `vector<int>[10k]` 的分配从 24 次降到 1 次，但整体明显退化，因此回退，仅保留 `emplace_back`。

## 已知遗留问题

以下问题尚未处理，与性能无关或需要 API 变更：

- 反序列化失败后目标对象可能已被部分修改
- 字符串读写不校验 UTF-8 合法性
- 输出 `span` 与输入对象存储重叠时为未定义行为
- `write_json` 会为每个 Writer 与 lambda 类型组合完整实例化，增加编译时间与二进制体积

## 测量注意事项

- 本机为笔记本平台，长时间高负载会触发降频。基准已下调大用例迭代次数以缩短总时长
- 若单次运行结果异常偏慢，建议先让 CPU 冷却，或使用过滤参数单独测量
- 吞吐按 JSON 字节数除以耗时计算，小对象的吞吐值受固定开销影响较大，横向比较应以 ns/op 为主
